# 🗂️ Portfolio as a Service (AI Edition)

A full-stack **multi-user portfolio platform** where anyone can sign up and get their own personalized portfolio website at `yourdomain.com/<username>` — with an **AI assistant embedded in every portfolio** that visitors can chat with about that person's work.

Built with **Next.js**, **Express**, **PostgreSQL**, **Prisma**, **Ollama**, and the **Model Context Protocol (MCP)**, deployed on **Vercel**.

🔗 **Live Demo:** [my-portfolio-ai-ten.vercel.app](https://my-portfolio-ai-ten.vercel.app)

---

## ✨ Features

- **Multi-user support** — each user gets a public portfolio at `/<username>`
- **JWT-based auth** — register, login, logout with secure HttpOnly cookies
- **Admin CMS** — manage all portfolio sections from a dedicated dashboard
- **AI Chat Assistant** — a chat-style interface (replacing the earlier CLI) embedded in every portfolio. It answers visitor questions about the owner's projects, skills, and experience, grounded in real data via MCP tool calls rather than a static script
- **MCP tool server** — a standalone Model Context Protocol server exposes the portfolio's `about`, `skills`, `projects`, `experience`, and `social links` data as callable tools, so the model fetches real data instead of hallucinating it
- **Ollama-powered inference** — chat responses are generated by a hosted `gpt-oss:120b` model served through [Ollama](https://ollama.com), called from the MCP bridge
- **Per-session conversations** — each visitor gets a random session ID (not their username) so chat histories stay private and aren't guessable
- **Cloudinary integration** — image uploads for projects and profile
- **Resume upload & download** — upload PDF resume, public download via `/<username>/download`
- **Contact form** — visitors can send messages stored in the database
- **Social links** — add and manage links to GitHub, LinkedIn, Twitter, etc.

## 🤖 AI Chat Assistant

Every portfolio ships with an embedded chat UI (`frontend/src/components/Hero.js`) that replaces the old command-line-style interaction with a proper chat interface — message bubbles, typing indicator, auto-scroll.

**Architecture:** the AI assistant runs as its **own service**, separate from the main CMS backend:

```
Visitor's browser
      │  POST { username, message, converId }
      ▼
frontend (Next.js)
      │
      ▼
mcp-portfolio-server  ──(HTTP /chat, Express)
      │
      ├─ MCP Client  ──(stdio)──▶  MCP Tool Server (src/index.ts)
      │                                  │
      │                                  ▼
      │                          backend CMS API (/api/about, /api/skills, ...)
      │
      └─ Ollama (gpt-oss:120b, hosted at ollama.com)
```

**How a request flows:**

1. The frontend generates a random per-browser session ID (`chat_session_id` in `localStorage`, via `crypto.randomUUID()`) and sends it as `converId` along with the visitor's `message` and the portfolio `username` to the MCP server's `/chat` endpoint.
2. On the first message of a conversation, the server fetches the portfolio owner's profile (via an MCP `resource`, `portfolio://users/{username}`) and seeds a system prompt that scopes the assistant to that person — "you are the AI assistant embedded in `<username>`'s portfolio," with instructions to always call tools rather than invent details, stay on topic, and keep answers conversational (no tables/JSON/markdown).
3. The message history for that `converId` is sent to **Ollama** (`gpt-oss:120b`) along with the list of tools discovered from the MCP server.
4. If the model requests a tool call (e.g. `get_projects`, `get_skills`), the bridge calls it against the MCP tool server, which in turn hits the real CMS backend API for that user's data, and feeds the result back to the model. This loops for up to 5 turns.
5. The final natural-language response is returned to the frontend and rendered in the chat.

### MCP tools exposed

The MCP tool server (`mcp-portfolio-server/src/index.ts`) registers the following tools, each optionally scoped by `username`:

| Tool | Description |
|---|---|
| `get_about` | Bio, headline, name, location |
| `get_skills` | Technical skills |
| `get_projects` | Projects, descriptions, tech stack |
| `get_experience` | Work experience (role, company, dates) |
| `get_social_links` | Social/professional links |

It also exposes a `portfolio://users/{username}` **resource** used to seed the assistant's system prompt with the owner's basic profile.

### Session handling

Conversations are keyed by the random `converId` (session ID) generated on the frontend — **not** the username — so one visitor can never read another visitor's (or another portfolio's) chat history just by guessing a name. Conversation state currently lives in an in-memory `Map` on the MCP server, so it resets on server restart/redeploy — worth moving to Redis or a DB if you need persistence across deploys.

## 🗄️ Database Schema

The Prisma schema covers the following models, all scoped per user:

- **User** — name, email, username, title, role (`admin` / `user`)
- **About** — heading, content, optional profile image
- **Skill** — name, category, level (0–100), icon, description
- **Project** — title, slug, short/long description, image, GitHub/live URLs, tech stack, featured flag
- **Experience** — company, role, location, description, start/end dates, `currentlyWorking` flag
- **Education** — institution, degree, field, grade, years
- **Certificate** — title, issuer, issue date, credential URL, image
- **Achievement** — title, description
- **SocialLink** — platform, URL, icon
- **Resume** — title, Cloudinary file URL
- **ContactMessage** — name, email, subject, message, `isRead` flag

## ⚙️ Getting Started

### Prerequisites

- Node.js 18+
- PostgreSQL database (e.g. [NeonDB](https://neon.tech))
- Cloudinary account
- An [Ollama](https://ollama.com) API key (this project calls the hosted `ollama.com` API rather than a local install)

### 1. Clone the repo

```bash
git clone https://github.com/thunDer2203/my_portfolio-ai.git
cd my_portfolio-ai
```

### 2. Set up the backend (CMS API)

```bash
cd backend
npm install
```

Create a `.env` file:

```env
DATABASE_URL=postgresql://user:password@host/dbname
JWT_SECRET=your_jwt_secret
FRONTEND_URL=http://localhost:3000
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret
PORT=5000
```

Run migrations and start:

```bash
npx prisma migrate dev
npm run dev
```

### 3. Set up the AI service (mcp-portfolio-server)

```bash
cd mcp-portfolio-server
npm install
```

Create a `.env` file:

```env
BASE_URL_API=http://localhost:5000/api
OLLAMA_API_KEY=your_ollama_api_key
FRONTEND_URL=http://localhost:3000
PORT=1143
```

Build the MCP tool server, then start the chat server (which connects to it over stdio and initializes Ollama):

```bash
npm run build
npm start
```

You should see `Connected to MCP server. Discovered 5 tools: ...` and `AI server running on port 1143`.

> To poke at just the MCP tool server on its own (outside the chat flow), use the [MCP Inspector](https://github.com/modelcontextprotocol/inspector):
> ```bash
> npx @modelcontextprotocol/inspector node build/index.js
> ```

### 4. Set up the frontend

```bash
cd frontend
npm install
```

Create a `.env.local` file:

```env
NEXT_PUBLIC_API_URL=http://localhost:5000
NEXT_PUBLIC_AI_API_URL=http://localhost:1143
```

Start the dev server:

```bash
npm run dev
```

The app will be running at `http://localhost:3000`.

## 🚀 Deployment

- **Frontend** — deploy to [Vercel](https://vercel.com). Set `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_AI_API_URL` to your backend and AI service URLs in Vercel's environment variables.
- **Backend (CMS API)** — deploy to Railway, Render, or any Node-compatible host. Set all `.env` variables in the platform's dashboard.
- **AI service (mcp-portfolio-server)** — deploy separately (or alongside the backend) on any Node host; it just needs outbound access to `BASE_URL_API` (your backend) and `ollama.com`. No GPU needed on your side since inference is hosted by Ollama.
- **Database** — [NeonDB](https://neon.tech) recommended (free tier available).
- After deploying the backend, run `npx prisma migrate deploy` to apply migrations in production.
